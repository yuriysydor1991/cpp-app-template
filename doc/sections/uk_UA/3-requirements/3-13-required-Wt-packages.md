## Обов'язкові пакунки для Wt

Гілка будує свій веб-сайт на [Wt C++ фреймворку](https://www.webtoolkit.eu/wt) 4. Під час конфігурування проекту спершу шукається встановлений у системі Wt, а якщо його немає, то вихідний код релізу Wt `4.11.4` завантажується з репозиторію [https://github.com/emweb/wt](https://github.com/emweb/wt) і будується разом з проектом: лише вбудований httpd конектор, без серверних частин баз даних Dbo, прикладів і тестів. Жоден з випусків Ubuntu 24.04/26.04 чи Debian 13 не містить пакунків Wt, тож там зазвичай будується саме завантажений вихідний код, для чого необхідні пакунки з підсекції [Пакети необхідні для побудови Wt](/doc/sections/uk_UA/3-requirements/3-13-3-packages-required-to-build-the-Wt.md).

Параметри конфігурування, що стосуються Wt:

- `ENABLE_WT4` (типово `ON`) робить Wt доступним для проекту. На ньому побудовані компонент `src/wt4` і клас `Application`, тож параметр лишається увімкненим, доки проект їх не позбудеться.
- `WT4_TRY_SYSTEM_PROBE` (типово `ON`) спершу шукає встановлений у системі Wt і лише потім завантажує його. Значення `OFF` вимагає завжди будувати завантажений вихідний код.
- `TEMPLATE_APP_WT4_GIT` і `TEMPLATE_APP_WT4_GIT_TAG` (типово `https://github.com/emweb/wt.git` і `4.11.4`) задають репозиторій і тег для завантаження.
- `WT4_DOCKER_PORT` (типово `8000`) задає порт, який слухає образ одиночного запуску docker і який публікується на loopback мережевому інтерфейсі.

Наприклад:

```
# з кореневої директорії проекту

cmake -S . -B build -DWT4_TRY_SYSTEM_PROBE=OFF
```
