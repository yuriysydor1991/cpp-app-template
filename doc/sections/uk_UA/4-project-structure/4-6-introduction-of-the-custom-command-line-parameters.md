## Впровадження нових параметрів командного рядка

Для того щоб впровадити нові параметри командного рядка для головного виконуваного файлу проекту-шаблона необхідно редагувати реалізацію класу `CommandLineParser`. Котрий у свою чергу містить методи розпізнавання параметрів командного рядка котрі передаються об'єктом класу `ApplicationFactory` після виклику головної функції `main` операційною системою.

Необхідно впровадити додаткові члени класу `ApplicationContext` щоб передавати додаткову інформацію з параметрів командного рядка до нащадків абстрактного класу `IApplication` (і відповідно впливати на їхню поведінку у відповідності до вводу користувача) що буде створений за допомогою обє'кта класу `ApplicationFactory` під час виконання розбору параметрів командного рядка.

Усі члени-дані класу `ApplicationContext` є приватними та мають префікс `m` у своїх назвах, тому для кожного нового поля необхідно оголосити відповідну пару публічних методів доступу, так само як це зроблено для вже наявних полів: метод читання з префіксом `get_` та метод запису з префіксом `set_` (наприклад, поле `mprint_help_and_exit` з методами `ApplicationContext::get_print_help_and_exit` та `ApplicationContext::set_print_help_and_exit`). Для значень, що використовуються одночасно декількома потоками, слід застосовувати типи на основі `std::atomic`, як це зроблено для вже наявного прапорця зупинки програми `mstop`.

Виконуваний файл проекту-шаблону вже приймає наступні параметри:

| Параметр | Дія |
| --- | --- |
| `-h`, `--help` | друкує довідку і завершує роботу з нульовим статусом |
| `-v`, `--version` | друкує версію, git-коміт побудови та дату конфігурації і завершує роботу з нульовим статусом |
| `-l <шлях>`, `--log-file <шлях>` | дописує повідомлення журналу до заданого файлу замість типового |

Метод `ApplicationFactory::run` розбирає параметри командного рядка до ініціалізації журналювання, отож програми друку довідки та версії взагалі не відкривають файлу журналу. Файл журналу, заданий параметром `-l`/`--log-file`, який неможливо відкрити, є помилкою: виконуваний файл друкує її до потоку stderr і завершує роботу з ненульовим статусом ще до запуску програми. Типовий файл журналу, який неможливо відкрити - наприклад у поточній робочій директорії, доступній лише для читання, - лише дає попередження, і журналювання продовжується у консоль.

Помилку розбору нового параметра слід повідомляти так само, як клас `CommandLineParser` повідомляє про невідомий параметр чи про відсутнє значення параметра: додати її опис методом `ApplicationContext::push_error`, підняти прапорець друку довідки методом `ApplicationContext::set_print_help_and_exit` і повернути значення `false`. Клас `ApplicationHelpPrinter` у такому разі друкує додані помилки до потоку stderr перед довідкою і повертає ненульовий статус, отож неправильне використання ніколи не звітує про успіх. Кожен новий параметр також необхідно зареєструвати у довідці класу `ApplicationHelpPrinter`.
