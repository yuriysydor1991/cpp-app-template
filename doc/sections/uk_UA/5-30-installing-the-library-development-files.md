## Встановлення файлів розробки бібліотеки

Встановлена динамічна бібліотека обслуговує дві різні аудиторії. Для запуску
програми, яку вже злінковано з бібліотекою, достатньо лише версійованого
бінарного файлу, який динамічний завантажувач знаходить через SONAME. Для
побудови *нової* програми з даною бібліотекою додатково необхідні файли
розробки: публічні заголовкові файли, файл pkg-config і файли інтеграції з
системою CMake.

Дистрибутиви розділяють ці дві групи на окремі пакунки - пакунок часу виконання
і пакунок `-dev` / `-devel`. Опція `LIB_INSTALL_DEV_FILES` дозволяє даному
проекту встановити або увесь набір, або лише половину часу виконання.

| Опція | За умовчанням | Дія |
|---|---|---|
| `-DLIB_INSTALL_DEV_FILES=true` | `true` | Встановлює бібліотеку часу виконання разом з файлами розробки |
| `-DLIB_INSTALL_DEV_FILES=false` | | Встановлює лише бібліотеку часу виконання |

Встановлення лише файлів часу виконання:

```
# у кореневій директорії проекту

meson setup build --prefix /usr/local -DLIB_INSTALL_DEV_FILES=false
ninja -C build
meson install -C build
```

Опцію також можна перемкнути для вже сконфігурованої директорії побудови:

```
meson configure build -DLIB_INSTALL_DEV_FILES=false
meson install -C build
```

Що саме встановлює кожен з режимів для проекту `CppAppTemplate` версії `0.12.0`:

| Встановлюваний артефакт | `true` | `false` |
|---|---|---|
| `<libdir>/libCppAppTemplate-0.12.so.0.12.0` - бінарний файл бібліотеки | так | так |
| `<libdir>/libCppAppTemplate-0.12.so.0` - символьне посилання SONAME для завантажувача | так | так |
| `<prefix>/include/CppAppTemplate-0.12/*.h` - публічні заголовкові файли | так | ні |
| `<libdir>/pkgconfig/CppAppTemplate-0.12.pc` - файл pkg-config | так | ні |
| `<libdir>/cmake/CppAppTemplate-0.12/*.cmake` - інтеграція з `find_package` | так | ні |
| символи зневадження, якщо проект їх встановлює | так | ні |

Даний шаблон не встановлює власних окремих файлів символів зневадження -
побудова у режимі `debug` утримує інформацію зневадження всередині самого
бінарного файлу бібліотеки. Дана опція є саме тим місцем, де слід обмежити таке
правило встановлення, якщо похідний проект його додасть. Система Meson також
уміє відкидати символи зневадження зі встановлюваних бінарних файлів за
допомогою `meson install --strip` - це незалежний перемикач, на який дана опція
не впливає.

Один з файлів розробки неможливо відокремити засобами Meson: неверсійоване
символьне посилання `<libdir>/libCppAppTemplate-0.12.so`, яке потрібне лише
лінкеру для пошуку за прапорцем `-lCppAppTemplate-0.12`. Meson встановлює увесь
ланцюжок символьних посилань як єдине ціле разом з ціллю `library()`, тому воно
встановлюється в обох режимах. Гілки даного шаблону на основі CMake прибирають
його за допомогою `NAMELINK_SKIP`.

Вимкнення опції жодним чином не змінює те, що саме *будується* - прибираються
лише правила встановлення. Тому одне і те саме дерево побудови може бути
встановленим обома способами.

Опція оголошена у [meson_options.txt](/meson_options.txt) і використовується у [src/lib/meson.build](/src/lib/meson.build).

Дивись також розділ [Налаштування складових імені встановлюваної бібліотеки](/doc/sections/uk_UA/5-29-customizing-library-name-segments.md), який визначає ім'я для кожного з перелічених вище артефактів.
