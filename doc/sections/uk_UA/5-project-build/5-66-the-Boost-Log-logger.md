## Логер Boost.Log

Макроси журналювання файлу `src/log/log.h` ведуть журнал через клас `boost_log::BoostLogController` директорії `src/log/boost-log`, який налаштовує консольний та файловий приймачі (sinks) [Boost.Log](https://www.boost.org/doc/libs/release/libs/log/):

| Макрос | Куди пише журнал |
| --- | --- |
| `LOG_INIT_DEFAULTS()` | у консоль і файл `CppAppTemplate-<версія>.log` поточної директорії; якщо файл не вдається відкрити (наприклад, у поточній директорії лише для читання), це коштує одного попередження у стандартний потік помилок, а журнал пишеться лише в консоль |
| `LOG_INIT_PATH(шлях)` | у консоль і заданий файл, який називає параметр командного рядка `-l` (або `--log-file`); дає `false`, якщо файл не вдається відкрити |
| `LOG_INIT(шлях, рівень, printMessages)` | у заданий файл із заданим рівнем, а також у консоль, якщо `printMessages` дорівнює `true`; дає `false`, якщо файл не вдається відкрити |

Кожна ініціалізація замінює приймачі попередньої, тож повторна ініціалізація не записує жодного запису двічі. Приймач, який згодом зазнає збою (заповнений диск, видалена директорія журналу), відкидає свої записи замість того, щоб завершити процес. Записи йдуть через єдиний багатопотоковий логер (`severity_logger_mt`), тож журнал можуть вести всі потоки одночасно.

Макроси `LOGE`, `LOGW`, `LOGI`, `LOGD` та `LOGT` пишуть з рівнями Boost.Log `error`, `warning`, `info`, `debug` і `trace`, а CMake змінна `MAX_LOG_LEVEL` вилучає зі збірки повідомлення вищих рівнів:

```
cmake -S . -B build -DMAX_LOG_LEVEL=5
```
