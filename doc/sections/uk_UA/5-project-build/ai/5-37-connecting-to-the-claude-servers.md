## Підключення до серверів Claude

Anthropic публікує офіційні SDK для Python, TypeScript, Java, Go, Ruby, C# та PHP, але жодного для C++. Тому ця гілка звертається до [Claude API](https://platform.claude.com/docs/en/api/overview) напряму: клас `curli::CURLController` з директорії `src/CURL` виконує HTTPS-запит, а клас `claudei::ClaudeController` з директорії `src/claude` будує та читає JSON навколо нього. Жодної сторонньої обгортки API не використовується, тож єдиними залежностями є бібліотеки [libcurl](https://curl.se/libcurl/) та [nlohmann JSON](https://github.com/nlohmann/json), обидві увімкнені у цій гілці за замовчуванням через CMake-змінні `ENABLE_LIBCURL` та `ENABLE_NLOHMANN_JSON`.

Обидві бібліотеки беруться з системи, якщо вони встановлені, як описано у секції [Необхідні пакети для клієнта Claude](/doc/sections/uk_UA/3-requirements/3-12-required-packages-for-the-claude-client.md), інакше завантажуються зі своїх git-репозиторіїв. Кожен репозиторій та його теґ задаються власною CMake-змінною:

```
cmake -S . -B build -DTEMPLATE_APP_NLOHMANN_GIT_TAG=v3.11.3
```

### Запит до моделі

Згенерований виконуваний файл ставить [Claude](https://www.claude.com/) питання, задане параметром командного рядка `--question` (або `-q`), і виводить отриману відповідь:

```
./build/src/CppAppTemplate --token <ваш-токен-anthropic-api> --question "У чому сенс податків?"
```

Токен береться зі змінної середовища `ANTHROPIC_API_KEY`, якщо параметр `--token` (або `-t`) не задано, що тримає його поза командним рядком процесу, видимим кожному користувачу машини:

```
export ANTHROPIC_API_KEY=<ваш-токен-anthropic-api>

./build/src/CppAppTemplate --question "У чому сенс податків?"
```

За замовчуванням запитується модель `claude-opus-5`. Будь-яка інша, доступна для використаного токена, задається параметром `--model` (або `-m`):

```
./build/src/CppAppTemplate --model claude-sonnet-5 --question "У чому сенс податків?"
```

Виконуваний файл завершується з ненульовим статусом і описом помилки, якщо токен відхилено або відповіді не отримано. Без питання він лише виводить підказку про те, як його задати, тому компонентні тести проходять і без доступного токена.

### Запит, який будує контролер

Метод `claudei::ClaudeController::ask` надсилає одне повідомлення користувача на точку доступу `https://api.anthropic.com/v1/messages`:

```
{"model":"claude-opus-5","max_tokens":16000,"messages":[{"role":"user","content":"..."}]}
```

Три особливості цієї точки доступу варто памʼятати при розширенні класу:

- Поле `max_tokens` є **обовʼязковим** і обмежує довжину відповіді. Використане значення зберігається у полі `DEFAULT_MAX_TOKENS` класу.
- Заголовком авторизації є `x-api-key`, а не `Authorization: Bearer`, і поруч із ним обовʼязковим є заголовок `anthropic-version`.
- Відповідь надходить масивом типізованих блоків вмісту, а не одним рядком, тому метод `extract_answer` зʼєднує текст кожного блоку типу `text` і пропускає решту. Відповідь також може містити `stop_reason` зі значенням `refusal`, що метод повідомляє як помилку замість відповіді.

### Структура підсистеми

Клас `curli::CURLController` отримав метод `post`, який надсилає тіло запиту разом із набором заголовків і залишає код HTTP-статусу відповіді доступним через метод `last_response_code`. На відміну від методу `download`, метод `post` не застосовує переривання за низькою швидкістю і чекає значно довше, бо модель, що складає відповідь, тим часом не надсилає нічого через зʼєднання.

Клас `claudei::ClaudeController` приймає цей контролер аргументом конструктора, що дозволяє модульному тесту `UTEST_ClaudeController` перевіряти побудований запит і розібрану відповідь на підробленому транспорті взагалі без доступу до мережі. Клас `app::Application` керує контролером за значеннями, які клас `app::CommandLineParser` розміщує в екземплярі `app::ApplicationContext`.
