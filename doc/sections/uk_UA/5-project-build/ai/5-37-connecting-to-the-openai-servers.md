## Підключення до серверів OpenAI

OpenAI публікує офіційні SDK для Python, TypeScript, .NET, Java, Go та Ruby, але жодного для C++. Тому ця гілка звертається до [OpenAI API](https://developers.openai.com/api/docs) напряму: клас `curli::CURLController` з директорії `src/CURL` виконує HTTPS-запит, а клас `chatgpti::ChatGPTController` з директорії `src/chatgpt` будує і розбирає JSON навколо нього. Жодної сторонньої обгортки API не задіяно, тому єдиними залежностями є бібліотеки [libcurl](https://curl.se/libcurl/) та [nlohmann JSON](https://github.com/nlohmann/json), обидві з яких увімкнені на цій гілці за замовчуванням через CMake змінні `ENABLE_LIBCURL` та `ENABLE_NLOHMANN_JSON`.

Обидві бібліотеки використовуються з системи, якщо вони встановлені, як описано у секції [Необхідні пакети для клієнта ChatGPT](/doc/sections/uk_UA/3-requirements/3-12-required-packages-for-the-chatgpt-client.md), і завантажуються зі своїх git-репозиторіїв в іншому випадку. Кожен репозиторій і його тег є окремою CMake змінною:

```
cmake -S . -B build -DTEMPLATE_APP_NLOHMANN_GIT_TAG=v3.11.3
```

### Запитування моделі

Згенерований виконуваний файл ставить [ChatGPT](https://chatgpt.com/) питання, задане параметром командного рядка `--question` (або `-q`), і виводить отриману відповідь:

```
./build/src/CppAppTemplate --token <твій-токен-openai-api> --question "What is the point of taxes?"
```

Якщо параметр `--token` (або `-t`) пропущено, токен береться зі змінної середовища `OPENAI_API_KEY`, що тримає його поза командним рядком процесу, видимим кожному користувачеві машини:

```
export OPENAI_API_KEY=<твій-токен-openai-api>

./build/src/CppAppTemplate --question "What is the point of taxes?"
```

За замовчуванням запитується модель `gpt-5.6`, яка є псевдонімом флагманської моделі сімейства. Будь-яка інша, доступна для використаного токена, запитується параметром `--model` (або `-m`):

```
./build/src/CppAppTemplate --model gpt-5.6-terra --question "What is the point of taxes?"
```

Виконуваний файл завершується ненульовим статусом і описом помилки, якщо токен відхилено або відповіді не отримано. Без питання він лише виводить підказку про те, як його задати, тому компонентні тести продовжують проходити за відсутності токена.

### Запит, який будує контролер

Метод `chatgpti::ChatGPTController::ask` надсилає питання до точки доступу [responses](https://developers.openai.com/api/docs/api-reference/responses/create) за адресою `https://api.openai.com/v1/responses`:

```
{"model":"gpt-5.6","input":"..."}
```

Три особливості цієї точки доступу варто памʼятати, розширюючи клас:

- Заголовком авторизації є звичайний `Authorization: Bearer <токен>`, і жодного заголовка з версією API поруч не потрібно.
- Відповідь надходить як масив типізованих елементів виводу, а не як єдиний рядок, причому елемент з міркуваннями зазвичай передує елементу з повідомленням, тому метод `extract_answer` обходить кожен елемент типу `message` і зчіплює текст кожного його блока `output_text`. Документація точки доступу прямо застерігає від зчитування відповіді з першого елемента. Модель також може відхилити питання блоком `refusal` замість текстового, що метод повідомляє як помилку, а не як відповідь.
- Поле `max_output_tokens` не надсилається, на відміну від обовʼязкового поля `max_tokens` у деяких інших постачальників. Ця межа враховує і невидимі токени міркувань, тому помірне значення змушує точку доступу відповісти зі `status` рівним `incomplete`, витратити весь бюджет на міркування і взагалі не містити елемента з повідомленням. Встановлюй це поле лише разом із щедрим значенням.

### Структура підсистеми

Клас `curli::CURLController` виконує запит своїм методом `post`, який надсилає тіло разом із набором заголовків, повідомляє, чи несе відповідь успішний статус, через метод `last_response_successfull`, і тримає сам код доступним через метод `last_response_code`. Запитування першого з них тримає HTTP-статуси всередині транспорту, тому клас-клієнт не утримує власної сталої статусу. На відміну від його методу `download`, метод `post` не застосовує обриву за низькою швидкістю і чекає значно довше, бо модель, що складає відповідь, тим часом нічого не надсилає у зʼєднання. Решту можливостей цього класу дивись у секції [Вмикання інтеграції libcurl](/doc/sections/uk_UA/5-project-build/5-14-enabling-libcurl.md).

Клас `chatgpti::ChatGPTController` приймає цей контролер аргументом конструктора, що дозволяє юніт-тесту `UTEST_ChatGPTController` перевіряти побудований запит і розібрану відповідь на заміннику транспорту взагалі без доступу до мережі. Клас `app::Application` керує контролером зі значеннями, які клас `app::CommandLineParser` розміщує в екземплярі `app::ApplicationContext`.
