## Вмикання оцінювання пози OpenPose

Для того щоб увімкнути у проекті модель оцінювання пози COCO [OpenPose](https://github.com/CMU-Perceptual-Computing-Lab/openpose) (18 ключових точок COCO тіла), необхідно встановити значення `ON` для CMake змінної `ENABLE_OPENPOSE` (для гілки `appOpenPose` воно типове):

```
# в середині кореневої директорії проекту

cmake -S . -B build -DENABLE_OPENPOSE=ON
cmake --build build --target all
```

Програма цієї гілки побудована навколо OpenPose, тож тут ця опція обов'язкова: крок конфігурування CMake завершується з поясненням, якщо опцію вимкнено значенням `OFF`.

Модель Caffe COCO OpenPose виконує модуль DNN бібліотеки OpenCV, на якій побудовано гілку, тож іншої бібліотеки не потрібно, а модуль [cmake/enablers/ai/template-project-openpose-enabler.cmake](/cmake/enablers/ai/template-project-openpose-enabler.cmake) завантажує модель.

| Змінна | Що вона містить |
| --- | --- |
| `PROJECT_POSE_MODEL` | директорія мережі `pose_deploy_linevec.prototxt` і ваг `pose_iter_440000.caffemodel`, які завантажує програма, доки параметр командного рядка `--model` (або `-m`) не задає іншої, завантажена, якщо змінна порожня, тож нічого не завантажується, коли її задано |
| `TEMPLATE_APP_OPENPOSE_NETWORK_URL`, `TEMPLATE_APP_OPENPOSE_NETWORK_SHA256` | файл мережі, який завантажує конфігурування, і його контрольна сума SHA256, типово з репозиторію OpenPose, закріплений за його комітом |
| `TEMPLATE_APP_OPENPOSE_WEIGHTS_URL`, `TEMPLATE_APP_OPENPOSE_WEIGHTS_SHA256` | файл ваг, який завантажує конфігурування, і його контрольна сума SHA256, типово з дзеркала моделей OpenCV |
| `ENABLE_OPENPOSE_MODEL_DOWNLOAD` | завантажує модель у директорію `TEMPLATE_APP_POSE_MODELS_DIR` під час конфігурування, типово `ON` |
| `TEMPLATE_APP_POSE_MODELS_DIR` | директорія, в яку завантажуються моделі, типово `misc/models` дерева вихідних кодів |

### Модель

Параметр `--model` (або `-m`) приймає директорію моделі тіла COCO OpenPose: мережу Caffe `pose_deploy_linevec.prototxt` і ваги `pose_iter_440000.caffemodel`. Модель приймає кадр BGR, масштабований до висоти 368 пікселів, ширина якого зберігає співвідношення сторін кратно 16, значень (піксель - 128) / 256, так, як це робить OpenPose, і дає 57 карт восьмої частини розміру входу: 18 теплових карт ключових точок (ніс, шия, праві плече, лікоть і зап'ясток, ліві, праві стегно, коліно і щиколотка, ліві, праве око, ліве, праве вухо і ліве), карту фону і 38 полів спорідненості частин (PAF). Найвищий відгук кожної теплової карти ключової точки дає ключову точку одного тіла, так, як це робить приклад openpose бібліотеки OpenCV, а відсутність ключової точки з оцінкою щонайменше 0.1 означає відсутність тіла. Поля спорідненості частин, які групують ключові точки кількох тіл, лишаються для власного групування кількох людей.

Сервера моделей OpenPose від CMU більше немає, тож мережа надходить з репозиторію OpenPose, а ваги — з дзеркала моделей, яке використовують тести OpenCV.

Конфігурування завантажує 46 КБ мережу з репозиторію OpenPose, закріплену за його комітом, і 209 МБ ваг з дзеркала `dl.opencv.org` у директорію `misc/models/openpose-coco`, у директорію `misc/models` дерева вихідних кодів, поза директоріями побудови, які скрипти `scripts/build` стирають при кожному конфігуруванні, тож усі директорії побудови дерева вихідних кодів, хоч як вони звуться, поділяють одне завантаження, а файли `.gitignore` і `.dockerignore` тримають його поза комітами і docker-збірками. Кожен файл спершу перевіряється за контрольною сумою SHA256 (і видобувається зі свого архіву) у директорії `.part` поруч з моделями, тож перерване чи пошкоджене завантаження ніколи не сприймається за модель, а невдале лише попереджає, лишаючи параметр `--model` способом задати модель. Вимкніть завантаження параметром `-DENABLE_OPENPOSE_MODEL_DOWNLOAD=OFF` або вкажіть власну модель змінною `PROJECT_POSE_MODEL`.

### Встановлення моделі

Ліцензія OpenPose забороняє поширення моделі, тож ні крок встановлення, ні жоден пакунок її не містять: клас `app::DataLocator` файлу [src/app/DataLocator.h](/src/app/DataLocator.h) не знаходить встановленої копії, і встановлений виконуваний файл завантажує завантажену модель дерева вихідних кодів, а виконуваному файлу іншої машини потрібен параметр `--model`, що вказує на модель, яку завантажив її користувач.

### Ліцензії

OpenPose та його моделі поширюються під [академічною ліцензією OpenPose](https://github.com/CMU-Perceptual-Computing-Lab/openpose/blob/master/LICENSE), яка дозволяє лише некомерційне дослідницьке використання, забороняє поширення і скеровує комерційних користувачів до платної ліцензії Університету Карнегі-Меллон, тож перевірте, чи охоплено ваше використання моделі, перш ніж щось на ній будувати. OpenCV поширюється під ліцензією [Apache-2.0](https://github.com/opencv/opencv/blob/4.x/LICENSE).

### Компоненти

Директорія [src/MoCap](/src/MoCap) містить незалежні від рушія вихідні коди захоплення рухів тіла простору імен `mocap`, інтерфейс оцінювача яких реалізує рушій [src/OpenPose](/src/OpenPose) цієї гілки:

| Клас | Що він робить |
| --- | --- |
| `mocap::FrameSource` | читає кадри камери, зображення, послідовності зображень, відеофайлу чи потоку модулем videoio бібліотеки OpenCV, див. розділ [Вмикання інтеграції OpenCV](/doc/sections/uk_UA/5-project-build/5-65-enabling-the-OpenCV.md) |
| `mocap::IPoseEstimator` | інтерфейс рушіїв оцінювання пози: завантажує модель і оцінює пози кадру BGR, а виклик `create` надає рушій, який долучає збірка |
| `mocap::MotionCapture` | оцінює пози кожного кадру, який читає `FrameSource`, засобами `IPoseEstimator` |
| `openpose::OpenPoseController` | оцінює позу моделлю Caffe COCO OpenPose засобами модуля OpenCV DNN |
| `openpose::HeatmapDecoder` | декодує ключові точки одного тіла з найвищих відгуків теплових карт ключових точок |

Кожна поза — це ключові точки тіла в порядку ключових точок моделі, а кожна ключова точка — кортеж її положення в пікселях кадру (глибина нульова) та її оцінки. Виклик `init` класу `mocap::MotionCapture` файлу [src/MoCap/MotionCapture.h](/src/MoCap/MotionCapture.h) завантажує модель, а виклик `open` відкриває вхід: камеру заданого індексу (`0` — типова камера) або зображення, послідовність зображень (`frame_%03d.png`), відеофайл чи URL потоку заданого шляху. Кожен виклик `capture` оцінює пози наступного кадру (порожні, якщо тіла немає) або повертає `std::nullopt` наприкінці входу чи у разі збою, який записує в журнал макрос `LOGE`:

```
#include "src/MoCap/MotionCapture.h"

auto capture = mocap::MotionCapture::create();

if (capture->init(model) && capture->open("dance.mp4")) {
  while (const auto poses = capture->capture()) {
    for (const auto& pose : *poses) {
      const auto& [position, score] = pose.front();
      // position.x, position.y і position.z першої ключової точки
    }
  }
}
```

Виклик `estimate` інтерфейсу `mocap::IPoseEstimator` оцінює пози власного кадру, а визначення `mocap::IPoseEstimator::create` у вихідних кодах рушія обирає рушій, тож інший рушій займає місце OpenPose заміною одного класу.
