## Вмикання перекладів GNU gettext

Для того щоб перекладати повідомлення проекту мовою користувача за допомогою каталогів повідомлень [GNU gettext](https://www.gnu.org/software/gettext/), необхідно встановити значення `ON` для CMake змінної `ENABLE_GETTEXT` (для гілки `appGettext` це значення за замовчуванням):

```
# в середині кореневої директорії проекту

cmake -S . -B build -DENABLE_GETTEXT=ON
cmake --build build --target all
```

Модуль [cmake/enablers/i18n/template-project-gettext-enabler.cmake](/cmake/enablers/i18n/template-project-gettext-enabler.cmake) шукає бібліотеку libintl, яка в ОС на базі GNU/Лінукс є частиною бібліотеки GNU C, та інструменти gettext, які компілюють переклади, тому встанови їх (скрипти `scripts/packages/install-*.sh` також це роблять):

```
sudo apt install -y gettext
```

Дистрибутиви на базі RPM також називають пакет `gettext`, тоді як FreeBSD розділяє його на пакети `gettext-runtime` (libintl) і `gettext-tools`. Модуль надає libintl як ціль `Intl::Intl`, ту саму, яку створює модуль `FindIntl` CMake 3.20 і новіших, а для старіших версій CMake модуль будує її зі змінних `FindIntl`, тому прилінковуй її до своїх цільових об'єктів. Її директорія заголовків важлива на FreeBSD, базовий компілятор якої не шукає у директорії `/usr/local/include`, куди встановлюється заголовок libintl:

```
target_link_libraries(${PROJECT_BINARY_NAME} Intl::Intl)
```

### Переклад повідомлень

Підключи заголовок [src/gettext/tr.h](/src/gettext/tr.h) і передавай англійські повідомлення через виклик `gettexti::tr`, або через виклик `gettexti::trn` для повідомлення, яке залежить від кількості (наприклад, українська мова має три форми множини):

```
#include "src/gettext/tr.h"

std::cout << gettexti::tr("Usage:") << std::endl;
std::cout << count << " " << gettexti::trn("file", "files", count) << std::endl;
```

Передавай лише рядкові літерали, оскільки інструмент `xgettext` видобуває повідомлення для перекладу з вихідних кодів за іменами `tr` і `trn`. Коментар `// TRANSLATORS:` безпосередньо над викликом потрапляє до перекладачів як підказка. Так перекладаються повідомлення довідки та версії класів `ApplicationHelpPrinter` і `ApplicationVersionPrinter` і привітання методу `app::Application::run` файлу [src/app/applications/Application.cpp](/src/app/applications/Application.cpp), тоді як повідомлення макросів `LOGx` лишаються англійськими, оскільки журнали читають і переглядають розробники.

### Директорія po

Кожен файл `po/<мова>.po` перекладає повідомлення своєю мовою, наприклад файл [po/uk.po](/po/uk.po) - українською. Побудова компілює його у каталог `locale/<мова>/LC_MESSAGES/<ім'я бінарного файлу>.mo` дерева побудови (ціль `gettext-catalogs`), а встановлення розміщує каталог у директорії `share/locale` (тобто `CMAKE_INSTALL_LOCALEDIR`). Текстовий домен - це ім'я бінарного файлу проекту, тож перейменований проект зберігає свої переклади. Виклик `msgfmt --check` зупиняє побудову на зламаному перекладі, наприклад на пропущеній формі множини.

Ціль `gettext-pot` видобуває повідомлення вихідних кодів у шаблон `po/<ім'я бінарного файлу>.pot` дерева побудови, а ціль `gettext-update-po` зливає шаблон з кожним po файлом після зміни повідомлень вихідних кодів, тож перекладачі бачать нові та змінені повідомлення:

```
cmake --build build --target gettext-update-po
```

Нова мова починається з шаблону, наприклад німецька:

```
cmake --build build --target gettext-pot
msginit --input=build/po/CppAppTemplate.pot --locale=de_DE.UTF-8 --output-file=po/de.po
```

Перекладай файл у текстовому редакторі або за допомогою інструменту на кшталт [Poedit](https://poedit.net/) і знову збери проект: конфігурування само підхоплює новий po файл.

### Мова користувача

Клас `ApplicationFactory` прив'язує каталоги через клас `gettexti::GettextController` файлу [src/gettext/GettextController.h](/src/gettext/GettextController.h) перед запуском програми. Контролер вмикає локаль повідомлень середовища (змінні `LC_ALL`, `LC_MESSAGES` або `LANG`, тоді як змінна `LANGUAGE` може перелічити мови для спроби) і видає переклади в кодуванні UTF-8:

```
LANG=uk_UA.UTF-8 ./build/src/CppAppTemplate --help
```

Вмикається лише категорія повідомлень локалі, оскільки вся локаль користувача також перемикає форматування чисел: наприклад, виклики `std::stod` і `std::to_string` читають і пишуть `1,5` замість `1.5` під локаллю `uk_UA`.

Переклади з'являються лише тоді, коли локаль встановлена в системі, інакше libintl нічого не перекладає, навіть зі змінною `LANGUAGE`, а контролер записує попередження про це до журналу. Контейнерам на базі GNU/Лінукс зазвичай бракує локалей, тому встанови пакет `locales-all` (Debian, Ubuntu) або `glibc-langpack-uk` (Fedora, RHEL), тоді як FreeBSD містить свої локалі у базовій системі. Образи Docker і конвеєри CI гілки встановлюють пакет `locales-all`, тож тести перекладу українською мовою там виконуються, тоді як деінде вони пропускають себе без локалі.

### Пошук каталогів

Клас `gettexti::CatalogsLocator` видає директорію каталогів для прив'язки, першу наявну з:

| Директорія | Для чого |
| --- | --- |
| директорія `../share/locale` поруч з виконуваним файлом | встановлений або переміщений виконуваний файл, наприклад файл AppImage чи snap, змонтований будь-де, або файл DEB-пакета, встановленого з префіксом `/usr` |
| директорія `locale` дерева побудови | виконуваний файл, запущений з дерева побудови |
| директорія `CMAKE_INSTALL_FULL_LOCALEDIR` | решта випадків |

Шлях запущеного виконуваного файлу береться з посилання `/proc/self/exe` на Лінукс, тож виконуваний файл, запущений через `PATH`, також знаходить свої каталоги, а деінде - з першого аргументу командного рядка.

### Злиття з іншими гілками

Ім'я `gettexti::tr` не конфліктує з жодним макросом `_()` бібліотек GLib і wxWidgets, а переклади надходять в UTF-8, якого очікують інструментарії GTK, wxWidgets (`wxString::FromUTF8`) і Qt (`QString::fromUtf8`). GTK і Qt самі викликають `setlocale(LC_ALL, "")`, тому повертай категорію `LC_NUMERIC` до `"C"` після запуску інструментарію, якщо код читає чи пише числа з рухомою комою. Файли інтерфейсу `GtkBuilder` перекладають свої властивості `translatable="yes"` прив'язаним текстовим доменом за замовчуванням, щойно їхні повідомлення потраплять до po файлів (додай файли `.ui` до вихідних кодів цілі `gettext-pot`), тоді як гілки Qt і надалі перекладають свій QML інструментами Qt Linguist.

### Пакування

Пакети DEB, RPM і FreeBSD pkg містять скомпільовані каталоги разом з виконуваним файлом. Маніфест flatpak тримає їх всередині застосунку (опцію `separate-locales` вимкнено), оскільки однофайловий пакет не містить окремого розширення локалей, а snap компілює їх за допомогою пакета `gettext` зі своїх пакетів побудови.
