## Вмикання рушія JavaScript V8

Для того щоб увімкнути рушій JavaScript [V8](https://v8.dev/) для проекту, необхідно встановити значення `ON` для CMake змінної `ENABLE_V8` (для гілки `appV8` це значення за замовчуванням):

```
# в середині кореневої директорії проекту

cmake -S . -B build -DENABLE_V8=ON
cmake --build build --target all
```

V8 збирається лише власним набором інструментів Google, що триває години і займає десятки гігабайтів, тому, на відміну від інших модулів, модуль [cmake/enablers/scripting/template-project-v8-enabler.cmake](/cmake/enablers/scripting/template-project-v8-enabler.cmake) нічого не завантажує з мережі, а натомість шукає вже встановлений V8. Дистрибутиви на базі Debian постачають V8 у складі спільної бібліотеки [Node.js](https://nodejs.org/), тому встанови її пакет розробки (скрипти `scripts/packages/install-ubuntu.sh` і `scripts/packages/install-debian.sh` також це роблять):

```
sudo apt install -y libnode-dev
```

Пакет розміщує заголовки V8 у директорії `/usr/include/node` і також називає бібліотеку `libnode.so` іменами `libv8.so` і `libv8_libplatform.so`. Модуль надає знайдений V8 як ціль `V8::V8`, тому прилінковуй її до своїх цільових об'єктів:

```
target_link_libraries(${PROJECT_BINARY_NAME} V8::V8)
```

### Власна збірка V8

Щоб спрямувати модуль на власну збірку V8 (дивись посібники [Building V8 with GN](https://v8.dev/docs/build-gn) і [Getting started with embedding V8](https://v8.dev/docs/embed)), задай наперед змінні кешу, якими модуль виконує пошук:

| Змінна | Що вона тримає |
| --- | --- |
| `V8_INCLUDE_DIR` | директорію заголовку `v8.h`, тобто директорію `include` вихідних кодів V8 |
| `V8_LIBRARY` | бібліотеку V8, наприклад `libv8_monolith.a` монолітної збірки |
| `V8_LIBPLATFORM_LIBRARY` | бібліотеку платформи V8, непотрібну для монолітної збірки |
| `TEMPLATE_APP_V8_COMPILE_DEFINITIONS` | визначення, потрібні заголовкам V8 для відповідності збірці |

Заголовки V8 мають бачити ті самі визначення стиснення вказівників і пісочниці, з якими зібрано бінарний файл V8. Збірки Node.js не потребують жодного з них, тоді як збірка з типовими аргументами потребує обидва:

```
cmake -S . -B build \
  -DV8_INCLUDE_DIR=/шлях/до/v8/include \
  -DV8_LIBRARY=/шлях/до/v8/out/x64.release/obj/libv8_monolith.a \
  -DTEMPLATE_APP_V8_COMPILE_DEFINITIONS="V8_COMPRESS_POINTERS;V8_ENABLE_SANDBOX"
```

V8 зібрано без RTTI, тому модуль вимикає перевірку `vptr` [санітайзерів](/doc/sections/uk_UA/5-project-build/code-quality/5-13-enabling-sanitizers.md) для цілей, що лінкують ціль `V8::V8`.

Заголовки V8, починаючи з версії 13.x (наприклад, `libnode-dev` з Node.js 24), вимагають C++20, тому модуль піднімає цілі, що лінкують ціль `V8::V8`, до C++20, тоді як решта проєкту лишається на C++17.

### Компоненти

Директорія [src/V8](/src/V8) містить три невеликі класи простору імен `v8i`:

| Клас | Що він робить |
| --- | --- |
| `V8Platform` | ініціалізує весь V8 один раз на процес (дані ICU, стартовий знімок, платформу і сам рушій) і звільняє його при завершенні процесу, оскільки після звільнення V8 вже ніколи не ініціалізується повторно |
| `V8Console` | замінює обʼєкт `console` контексту на такий, що пише у журнал проекту |
| `V8Controller` | ініціалізує V8 через `V8Platform`, володіє власним ізолятом з контекстом і виконує в ньому код JavaScript |

Виклик `init` класу `v8i::V8Controller` з файлу [src/V8/V8Controller.h](/src/V8/V8Controller.h) приймає шлях до виконуваного файлу, оскільки збірки V8, що тримають дані ICU і стартовий знімок в окремих файлах, шукають їх поруч з ним. Виклик `run` компілює і виконує код під заданим іменем скрипта і повертає значення завершення, перетворене на рядок. Глобальні змінні, оголошені одним виконанням, лишаються доступними наступним виконанням того самого контролера, тоді як кожен контролер має власний контекст.

```
auto engine = v8i::V8Controller::create();

if (engine->init(argv[0])) {
  engine->run("var answer = 6 * 7", "first.js");

  // записує у журнал повідомлення "second.js:1 : The answer is 42" і повертає "42"
  const auto result = engine->run("console.log('The answer is', answer); answer", "second.js");
}
```

Ніщо не викидає винятків: помилка компіляції чи неперехоплений виняток записуються макросом `LOGE` разом з розташуванням у скрипті (наприклад, `throwing.js:3 : Uncaught Error: boom`), а виклик `run` повертає `std::nullopt`.

### Консоль

Методи обʼєкта `console` записують свої аргументи, перетворені на рядки і зʼєднані пробілами, через екземпляр `LOG_REAL_LOGGER`, тож повідомлення потрапляють у той самий файл журналу і стандартний вивід, куди пишуть макроси `LOGx`. Повідомлення містить імʼя файлу JavaScript і номер рядка виклику замість C++ відповідників:

| Метод | Рівень журналу |
| --- | --- |
| `console.log`, `console.info` | інформаційний |
| `console.warn` | попередження |
| `console.error` | помилка |
| `console.debug` | налагодження |
| `console.trace` | трасування |

```
2026-10-05 18:25:16 INF 140370990078208 main.js:1 : Hello, V8! Insert your JavaScript code here!
```

Рівень журналу відфільтровує повідомлення консолі так само, як і будь-які інші, тому підвищ значення CMake змінної `MAX_LOG_LEVEL`, щоб побачити повідомлення `console.debug` і `console.trace`.

Метод `app::Application::run` з файлу [src/app/applications/Application.cpp](/src/app/applications/Application.cpp) виконує код `console.log("Hello, V8! Insert your JavaScript code here!")`, тож заміни його власним кодом JavaScript.

### Пакування

Пакет DEB залежить від пакету `libnode`, з яким злінковано виконуваний файл, через інструмент `dpkg-shlibdeps`, оскільки кожен випуск дистрибутиву називає його власною версією ABI (наприклад, `libnode109` чи `libnode127`). Пакет snap додає пакет `libnode109` своєї бази `core24`, тоді як flatpak спершу збирає спільну бібліотеку Node.js з вихідних кодів, що триває певний час.
