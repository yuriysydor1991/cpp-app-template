## Обмеження захисту (hardening) HTTP-клієнта

[CURLController](/src/CURL/CURLController.cpp) шаблону не виконує жодного запиту без обмежень, які не дають ворожій чи зіпсованій відповіді вичерпати ресурси застосунку, отож вмикати для цього нічого не потрібно. Кожне обмеження є змінною кешу CMake модуля [cmake/template-project-misc-variables-declare.cmake](/cmake/template-project-misc-variables-declare.cmake), яку шаблон [src/project-global-decls.h.in](/src/project-global-decls.h.in) перетворює на сталу часу компіляції простору імен `project_decls`:

| Змінна CMake | Типове значення | Що обмежує |
| --- | --- | --- |
| `PROJECT_CURL_MAX_RESPONSE_BYTES` | `8388608` (8 МіБ) | розмір тіла відповіді, яку може отримати один запит |
| `PROJECT_CURL_CONNECT_TIMEOUT_SECONDS` | `10` | час, який може тривати встановлення з'єднання |
| `PROJECT_CURL_TRANSFER_TIMEOUT_SECONDS` | `30` | час, який може тривати ціле звантаження чи перевірка досяжності |
| `PROJECT_CURL_POST_TIMEOUT_SECONDS` | `300` | час, який може тривати цілий запит POST |
| `PROJECT_CURL_ALLOWED_PROTOCOLS` | `http,https,file` | протоколи, які може використовувати URL запиту |

Побудова, яка стискає кожне з них, виглядає так:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DPROJECT_CURL_MAX_RESPONSE_BYTES=1048576 \
  -DPROJECT_CURL_CONNECT_TIMEOUT_SECONDS=5 \
  -DPROJECT_CURL_TRANSFER_TIMEOUT_SECONDS=15 \
  -DPROJECT_CURL_POST_TIMEOUT_SECONDS=60 \
  -DPROJECT_CURL_ALLOWED_PROTOCOLS=https
```

### Обмеження розміру відповіді

Відповідь, яка оголошує розмір понад дозволений, відхиляється параметром `CURLOPT_MAXFILESIZE_LARGE` бібліотеки libcurl ще до передавання жодного її байта. Відповідь, яка не оголошує розміру взагалі - частинами (chunked), наприклад - натомість обрізається зворотним викликом запису, який припиняє дописування, щойно буфер переріс би межу, і цим перериває усе передавання:

```
ERR CURLController.cpp:112 : The response has outgrown the allowed 8388608 bytes
```

Отриманий буфер залишається порожнім в обох випадках, а виклик `last_response_successfull` повідомляє про невдачу, отож частково отриману відповідь ніколи не сприймають за повну.

### Час очікування

Час очікування з'єднання застосовується до кожного різновиду запиту, а час передавання відокремлює звичайне звантаження та перевірку досяжності від запиту POST: сервер, який складає відповідь, тримає з'єднання мовчазним увесь цей час, що короткий час очікування сприйняв би за зупинку. Звантаження додатково перериває передавання, яке повзе нижче одного байта за секунду протягом десяти секунд (параметри `CURLOPT_LOW_SPEED_LIMIT` та `CURLOPT_LOW_SPEED_TIME`), чого POST не робить саме з наведеної причини.

Параметр `CURLOPT_NOSIGNAL` увімкнено, отож час очікування не здіймає жодного сигналу, а контролер залишається придатним до використання з власного потоку.

### Дозволені протоколи

Параметр `CURLOPT_PROTOCOLS_STR` обмежує запит протоколами переліку `PROJECT_CURL_ALLOWED_PROTOCOLS`, отож зловмисно складений URL не дістається жодної служби `scp`, `smb` чи `dict` локальної мережі. Протокол `file` дозволено типово, бо сам шаблон та його компонентний тест звантажують саме через нього; застосункові, який бере свої URL із ненадійного джерела, слід звузити перелік до самого лише `https`, що також не залишає жодного локального файлу читабельним через запит.

Параметр з'явився у випуску libcurl 7.85.0 і застосовується лише новішою бібліотекою, отож старіша libcurl зберігає протоколи власної побудови. Назва протоколу, якої libcurl не знає, провалює запит із повідомленням, що називає змінну для виправлення:

```
ERR CURLController.cpp:194 : Fail to allow the htttp protocols only. Check the PROJECT_CURL_ALLOWED_PROTOCOLS value
```

### Обмеження TLS

| Параметр libcurl | Значення | Що виконує |
| --- | --- | --- |
| `CURLOPT_SSL_VERIFYPEER` | `1` | сертифікат сервера перевіряється за центрами сертифікації системи |
| `CURLOPT_SSL_VERIFYHOST` | `2` | назва вузла сертифіката звіряється з назвою вузла URL |
| `CURLOPT_SSLVERSION` | `CURL_SSLVERSION_TLSv1_2` | TLS 1.2 є найнижчою прийнятною версією протоколу |

Перші два вже є типовими значеннями libcurl і встановлюються попри це, щоб ані побудова з іншим типовим значенням, ані нащадок не знизили їх непомітно. Перехід за переспрямуванням залишається вимкненим, яким він є і типово, отож заголовок авторизації запиту дістається запитаного вузла і жодного іншого.

### Перевірка результату

Значення, які взяла побудова, містяться у створеному заголовку `project-global-decls.h` каталогу побудови:

```bash
grep PROJECT_CURL build/project-global-decls.h
```

Компонентний тест [CTEST_CURLController](/src/CURL/tests/component/CURLController/CTEST_CURLController.cpp) перевіряє, що відповідь понад дозволений розмір відхиляється, а модульний тест [UTEST_CURLController](/src/CURL/tests/unit/CURLController/UTEST_CURLController.cpp) перевіряє, що буфер припиняє зростати рівно на межі.
