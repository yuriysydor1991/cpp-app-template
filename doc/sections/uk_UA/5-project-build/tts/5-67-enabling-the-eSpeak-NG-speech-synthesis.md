## Вмикання синтезу мовлення eSpeak NG

Для того щоб увімкнути у проекті бібліотеку синтезу мовлення [eSpeak NG](https://github.com/espeak-ng/espeak-ng) (компактний формантний синтезатор понад сотні мов і акцентів), необхідно встановити значення `ON` для CMake змінної `ENABLE_ESPEAK_NG` (для гілки `appESpeakNG` це значення за замовчуванням):

```
# в середині кореневої директорії проекту

cmake -S . -B build -DENABLE_ESPEAK_NG=ON
cmake --build build --target all
```

Програма цієї гілки побудована навколо eSpeak NG, тож тут ця опція обов'язкова: крок конфігурування CMake завершується з поясненням, якщо опцію вимкнено значенням `OFF`.

Модуль [cmake/enablers/tts/template-project-espeak-ng-enabler.cmake](/cmake/enablers/tts/template-project-espeak-ng-enabler.cmake) бере встановлену в системі eSpeak NG через модуль `espeak-ng` інструмента `pkg-config`, оскільки бібліотека під час роботи читає дані голосів своєї інсталяції. Встанови її пакет розробки (це роблять скрипти `scripts/packages`):

```
sudo apt install -y pkg-config libespeak-ng-dev
```

У дистрибутивах на базі RPM це пакет `espeak-ng-devel`, у FreeBSD - `audio/espeak-ng`. Без бібліотеки конфігурування завершується з повідомленням, яке їх називає, а власну інсталяцію бібліотеки знаходить змінна оточення `PKG_CONFIG_PATH`, що вказує на її файл `espeak-ng.pc`. Модуль надає ціль `ESpeakNG::espeak-ng`, тож прилінковуй її до своїх цільових об'єктів:

```
target_link_libraries(${PROJECT_BINARY_NAME} ESpeakNG::espeak-ng)
```

| Змінна | Що вона містить |
| --- | --- |
| `PROJECT_TTS_TEXT` | текст, який промовляє програма, поки параметр командного рядка `--text` (або `-t`) не задає іншого, за замовчуванням `Hello, eSpeak NG! Insert your text here!` |
| `PROJECT_TTS_VOICE` | голос, яким промовляє програма, поки параметр командного рядка `--voice` (або `-s`) не задає іншого, за замовчуванням `en` |

### Ліцензія

eSpeak NG поширюється за ліцензією [GPL-3.0-or-later](https://github.com/espeak-ng/espeak-ng/blob/master/COPYING). Виконуваний файл лінкує бібліотеку, тож поширюваний іншим виконуваний файл (у пакеті, в образі чи як є) є поєднаним з нею твором і має поширюватися загалом на умовах GPL-3.0 (або пізнішої версії): з повними відповідними вихідними кодами і тими самими правами для його користувачів. Власні вихідні коди проекту можуть мати свою сумісну з GPL ліцензію, а проект, який не може поширювати свій виконуваний файл у такий спосіб, обирає рушій мовлення з іншою ліцензією. Пакети гілки (DEB, flatpak, snap тощо) містять бібліотеку або залежать від неї, тож на них також поширюються ці умови.

### Голоси

eSpeak NG називає свої голоси кодами мов (`en`, `uk`, `de`, `fr` тощо), кодами акцентів (`en-us`, `en-gb-scotland` тощо) або повними назвами (`gmw/en-US`), а варіант голосу додається після знака плюс (`en+f3` для жіночого). Команда `espeak-ng --voices` перелічує встановлені голоси, а команда `espeak-ng --voices=uk` - голоси однієї мови. Бібліотека промовляє кожним голосом з частотою 22,05 кГц.

Найперший синтез ініціалізує бібліотеку за шляхом до даних її інсталяції, а змінна оточення `ESPEAK_DATA_PATH` вказує на іншу директорію `espeak-ng-data` (або на директорію, яка її містить):

```
ESPEAK_DATA_PATH=/opt/espeak-ng/share ./src/CppAppTemplate --voice uk --text "Привіт!"
```

### Складові

Директорія [src/ESpeakNG](/src/ESpeakNG) містить єдиний клас `espeakng::ESpeakNGController` - рушій мовлення гілки. Він реалізує інтерфейс `tts::ISpeechSynthesizer` незалежних від рушія вихідних кодів [src/TTS](/src/TTS):

| Клас | Що він робить |
| --- | --- |
| `tts::Speech` | зберігає синтезовані монофонічні 16-бітні відліки з їхньою частотою і тривалістю |
| `tts::ISpeechSynthesizer` | інтерфейс рушіїв мовлення: промовляє заданий текст заданим голосом у `tts::Speech`, а виклик `create` надає рушій, який лінкує збірка |
| `tts::WavWriter` | записує `tts::Speech` у 16-бітний монофонічний WAV-файл PCM |
| `tts::AudioPlayer` | відтворює `tts::Speech` типовим пристроєм відтворення звуку, дивись розділ [Вмикання відтворення звуку SDL2](/doc/sections/uk_UA/5-project-build/audio/5-68-enabling-the-SDL2-audio-playback.md) |
| `espeakng::ESpeakNGController` | синтезує мовлення засобами eSpeak NG |

Виклик `synthesize` контролера під час першого виклику ініціалізує бібліотеку (у синхронному режимі, в якому виклик повертається з усім зібраним мовленням), обирає голос і синтезує текст у кодуванні UTF-8, повертаючи `std::nullopt` у разі невдачі: ініціалізації, невідомого голосу чи самого синтезу, кожну з яких записано у журнал макросом `LOGE`. Знищення контролера завершує роботу бібліотеки, яка тримає єдиний стан на процес, тож тримай лише один контролер водночас:

```
auto synthesizer = tts::ISpeechSynthesizer::create();

if (const auto speech = synthesizer->synthesize("Привіт, світе!", "uk")) {
  tts::WavWriter::create()->write(*speech, "speech.wav");
}
```

Метод `app::Application::run` з файлу [src/app/applications/Application.cpp](/src/app/applications/Application.cpp) промовляє текст і голос командного рядка, записуючи мовлення у WAV-файл параметра `--output` (або `-o`) чи відтворюючи його в іншому разі. Він знає лише інтерфейси вихідних кодів `src/TTS`, тож інший рушій заступає eSpeak NG власною директорією `src/<рушій>`, яка визначає виклик `tts::ISpeechSynthesizer::create`, і своїм модулем CMake: саме так роблять гілки `appRHVoice`, `appPiperTTS` і `appSherpaONNX`.

### Тести

Тест `UTEST_ESpeakNGController` перевіряє контролер з імітацією викликів бібліотеки eSpeak NG, тож охоплює кожну невдачу бібліотеки, а тести `CTEST_ESpeakNGController` і `CTEST_app` синтезують англійське й українське мовлення справжньою бібліотекою, перевіряють записані WAV-файли і відтворюють мовлення аудіодрайвером `dummy` бібліотеки SDL2, тож звукова карта не потрібна.

### Пакування

Пакет DEB залежить від пакетів eSpeak NG і SDL2, які лінкує виконуваний файл, через інструмент `dpkg-shlibdeps`, а пакет `libespeak-ng1` приносить із собою дані голосів. Flatpak збирає випуск `1.52.0` eSpeak NG з вихідних кодів разом з даними голосів у директорію `/app/share/espeak-ng-data` і бере SDL2 середовища виконання freedesktop, а snap додає до себе eSpeak NG, її дані та SDL2 з архіву Ubuntu і вказує на ці дані змінною `ESPEAK_DATA_PATH`. Flatpak відтворює мовлення через сокет PulseAudio і записує файли параметра `--output` у домашню директорію, а snap відтворює його через інтерфейс `audio-playback`.
