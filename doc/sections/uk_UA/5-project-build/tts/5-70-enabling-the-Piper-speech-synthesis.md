## Вмикання синтезу мовлення Piper

Для того щоб увімкнути у проекті бібліотеку синтезу мовлення [Piper](https://github.com/OHF-Voice/piper1-gpl) (швидкий локальний нейронний синтез мовлення багатьма мовами, її C/C++ бібліотека `libpiper`), необхідно встановити значення `ON` для CMake змінної `ENABLE_PIPER` (для гілки `appPiperTTS` це значення за замовчуванням):

```
# в середині кореневої директорії проекту

cmake -S . -B build -DENABLE_PIPER=ON
cmake --build build --target all
```

Програма цієї гілки побудована навколо Piper, тож тут ця опція обов'язкова: крок конфігурування CMake завершується з поясненням, якщо опцію вимкнено значенням `OFF`.

Жодна система не пакує `libpiper`, тож модуль [cmake/enablers/tts/template-project-piper-enabler.cmake](/cmake/enablers/tts/template-project-piper-enabler.cmake) збирає її з вихідних кодів випуску `v1.8.0` (змінні `TEMPLATE_APP_PIPER_GIT` і `TEMPLATE_APP_PIPER_GIT_TAG`) як окремий проект CMake у директорії `<build>/piper`, осторонь попереджень і перевірок проекту. Збірка `libpiper` завантажує і статично збирає зафіксовану версію [espeak-ng](https://github.com/espeak-ng/espeak-ng), якою вона перетворює текст на фонеми, разом з її даними `espeak-ng-data`, тож їй потрібні git і доступ до інтернету. Голоси виконує [onnxruntime](https://onnxruntime.ai/): модуль бере встановлену в системі бібліотеку через її пакет CMake, а інакше збірка `libpiper` завантажує готову версію `1.22.0` для GNU/Linux (x86-64, ARM), MS Windows чи macOS. Встанови її пакет розробки, якщо система його має (це роблять скрипти `scripts/packages`):

```
sudo apt install -y libonnxruntime-dev
```

Debian 13 і Ubuntu 26.04 пакують її як `libonnxruntime-dev`, Fedora - як `onnxruntime-devel`, FreeBSD - як `misc/onnxruntime` (готової версії для FreeBSD немає), а Ubuntu 24.04 такого пакету не має і бере завантажену. onnxruntime з Ubuntu 26.04 під час завантаження голосу виводить у стандартний потік помилок нешкідливі рядки `Schema error`. Власну інсталяцію onnxruntime знаходить змінна `CMAKE_PREFIX_PATH`. espeak-ng обмежує шляхи до своїх даних 160 символами, тож шлях до директорії збірки має бути коротшим приблизно за 90 символів, інакше компіляція даних espeak-ng аварійно завершується з повідомленням `buffer overflow detected`. Модуль надає ціль `Piper::piper`, тож прилінковуй її до своїх цільових об'єктів:

```
target_link_libraries(${PROJECT_BINARY_NAME} Piper::piper)
```

| Змінна | Що вона містить |
| --- | --- |
| `PROJECT_TTS_TEXT` | текст, який промовляє програма, поки параметр командного рядка `--text` (або `-t`) не задає іншого, за замовчуванням `Hello, Piper! Insert your text here!` |
| `PROJECT_TTS_VOICE` | модель голосу, якою промовляє програма, поки параметр командного рядка `--voice` (або `-s`) не задає іншої, якщо порожня - завантажена `<build>/voices/<TEMPLATE_APP_PIPER_VOICE>.onnx` |
| `TEMPLATE_APP_PIPER_VOICE` | голос, який завантажує конфігурування, за замовчуванням `en_US-lessac-medium` |
| `ENABLE_PIPER_VOICE_DOWNLOAD` | під час конфігурування завантажує голос `TEMPLATE_APP_PIPER_VOICE` у директорію `<build>/voices` і встановлює його разом з виконуваним файлом, за замовчуванням `ON` |
| `TEMPLATE_APP_PIPER_VOICES_URL` | зафіксована ревізія репозиторію [rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices), з якої завантажується голос |

### Ліцензія

Piper поширюється за ліцензією [GPL-3.0-or-later](https://github.com/OHF-Voice/piper1-gpl/blob/main/COPYING), вбудована в неї espeak-ng - теж за GPL-3.0-or-later. Виконуваний файл лінкує бібліотеку, тож поширюваний іншим виконуваний файл (у пакеті, в образі чи як є) є поєднаним з нею твором і має поширюватися загалом на умовах GPL-3.0 (або пізнішої версії): з повними відповідними вихідними кодами і тими самими правами для його користувачів. Власні вихідні коди проекту можуть мати свою сумісну з GPL ліцензію, а проект, який не може поширювати свій виконуваний файл у такий спосіб, обирає рушій мовлення з іншою ліцензією. Пакети гілки (DEB, flatpak, snap тощо) містять бібліотеку, тож на них також поширюються ці умови, а onnxruntime поширюється за ліцензією MIT.

Кожен голос має власну ліцензію - ліцензію набору даних, на якому його навчено, яку називає файл `MODEL_CARD` поруч із голосом у репозиторії голосів: голос `en_US-lessac-medium` навчено на наборі даних [Lessac Blizzard 2013](https://www.cstr.ed.ac.uk/projects/blizzard/2013/lessac_blizzard2013/license.html) з його власними умовами ліцензії, а голос `uk_UA-ukrainian_tts-medium` - на наборі даних CC0. Перевір ліцензію голосу, перш ніж поширювати його чи мовлення, яке він промовляє, зокрема пакети, зібрані із завантаженим голосом (дивись встановлення голосу нижче), а параметр `-DENABLE_PIPER_VOICE_DOWNLOAD=OFF` залишає голос поза ними.

### Голоси

Голос Piper - це модель `.onnx` з файлом налаштувань `.onnx.json` такої ж назви поруч, названа за мовою, регіоном, назвою та якістю (`en_US-lessac-medium`). Конфігурування завантажує голос `TEMPLATE_APP_PIPER_VOICE` у директорію `<build>/voices`, перевіряючи контрольні суми SHA256 відомих голосів, тож програма директорії збірки промовляє ним. Параметр `--voice` (або `-s`) приймає шлях до будь-якого іншого голосу, наприклад, українського `uk_UA-ukrainian_tts-medium`:

```
cmake -S . -B build -DTEMPLATE_APP_PIPER_VOICE=uk_UA-ukrainian_tts-medium
cmake --build build
./build/src/CppAppTemplate --voice build/voices/uk_UA-ukrainian_tts-medium.onnx --text "Привіт, світе!"
```

Файл [VOICES.md](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/VOICES.md) перелічує голоси та зразки їхнього мовлення. Голоси середньої якості промовляють з частотою 22,05 кГц, а мовлення бере частоту з налаштувань голосу.

Контролер передає бібліотеці директорію `espeak-ng-data` поруч із завантаженою `libpiper` (директорію `<build>/piper/lib` збірки чи `<prefix>/lib/<project>` інсталяції), тож її однаково знаходять і директорія збірки, і перенесені інсталяції (DEB, snap, AppImage тощо), а якщо її немає, її заступає змінна оточення `ESPEAK_DATA_PATH`. `libpiper` ініціалізує espeak-ng так, що відсутність даних завершує весь процес з повідомленням espeak-ng `Error processing file`.

### Встановлення голосу

Завантажений голос є файлом дерева збірки, тож крок встановлення (а також кожен пакет, зібраний на його основі: deb, rpm, AppImage, пакет FreeBSD, інсталятор MS Windows) копіює його разом з налаштуваннями до директорії `<prefix>/share/<project>`, наприклад у файл `/usr/share/CppAppTemplate/en_US-lessac-medium.onnx`, і встановлена програма промовляє без дерева збірки. Клас `app::DataLocator` з файлу [src/app/DataLocator.h](/src/app/DataLocator.h) обирає голос, яким промовляє запущений виконуваний файл, поки параметр `--voice` не задає іншого: спершу встановлений відносно розташування виконуваного файлу (тож перенесений пакет, наприклад AppImage, і далі працює), потім завантажений у дерево збірки (виконуваний файл, запущений з нього), а потім встановлений за налаштованим префіксом. Вимкнене або невдале завантаження не встановлює жодного голосу, тож тоді встановленій програмі потрібен параметр `--voice`, а голос змінної `PROJECT_TTS_VOICE` завантажується з того місця, де він є.

### Складові

Директорія [src/PiperTTS](/src/PiperTTS) містить єдиний клас `pipertts::PiperController` - рушій мовлення гілки. Він реалізує інтерфейс `tts::ISpeechSynthesizer` незалежних від рушія вихідних кодів [src/TTS](/src/TTS):

| Клас | Що він робить |
| --- | --- |
| `tts::Speech` | зберігає синтезовані монофонічні 16-бітні відліки з їхньою частотою і тривалістю |
| `tts::ISpeechSynthesizer` | інтерфейс рушіїв мовлення: промовляє заданий текст заданим голосом у `tts::Speech`, а виклик `create` надає рушій, який лінкує збірка |
| `tts::WavWriter` | записує `tts::Speech` у 16-бітний монофонічний WAV-файл PCM |
| `tts::AudioPlayer` | відтворює `tts::Speech` типовим пристроєм відтворення звуку, дивись розділ [Вмикання відтворення звуку SDL2](/doc/sections/uk_UA/5-project-build/audio/5-68-enabling-the-SDL2-audio-playback.md) |
| `pipertts::PiperController` | синтезує мовлення засобами Piper |

Виклик `synthesize` контролера завантажує голос під час першого виклику з ним і використовує його повторно наступного разу, а інший голос його заміняє. Він синтезує текст у кодуванні UTF-8 частина за частиною, перетворюючи відліки Piper з рухомою комою на 16-бітні з частотою голосу, і повертає `std::nullopt` у разі невдачі: відсутності голосу, його завантаження (разом зі зламаними файлами, про які `libpiper` повідомляє винятками) чи самого синтезу, кожну з яких записано у журнал макросом `LOGE`. espeak-ng тримає єдиний стан на процес, тож тримай лише один контролер водночас:

```
auto synthesizer = tts::ISpeechSynthesizer::create();

if (const auto speech = synthesizer->synthesize("Hello!", "voices/en_US-lessac-medium.onnx")) {
  tts::WavWriter::create()->write(*speech, "speech.wav");
}
```

Метод `app::Application::run` з файлу [src/app/applications/Application.cpp](/src/app/applications/Application.cpp) промовляє текст і голос командного рядка, записуючи мовлення у WAV-файл параметра `--output` (або `-o`) чи відтворюючи його в іншому разі. Він знає лише інтерфейси вихідних кодів `src/TTS`, тож інший рушій заступає Piper власною директорією `src/<рушій>`, яка визначає виклик `tts::ISpeechSynthesizer::create`, і своїм модулем CMake: саме так роблять гілки `appESpeakNG`, `appRHVoice` і `appSherpaONNX`.

### Тести

Тест `UTEST_PiperController` перевіряє контролер з імітацією викликів `libpiper`, тож охоплює кожну невдачу бібліотеки, а тести `CTEST_PiperController` і `CTEST_app` синтезують англійське мовлення справжньою бібліотекою і завантаженим голосом, перевіряють записані WAV-файли і відтворюють мовлення аудіодрайвером `dummy` бібліотеки SDL2, тож звукова карта не потрібна. Випадки, що промовляють завантаженим голосом, пропускаються, якщо опцію `ENABLE_PIPER_VOICE_DOWNLOAD` вимкнено значенням `OFF`.

### Пакування

Інсталяція (а отже пакети DEB, RPM та інші) містить `libpiper`, завантажену onnxruntime (якщо системну не взято) і дані `espeak-ng-data` у директорії `<prefix>/lib/<project>`, де виконуваний файл знаходить їх за своїм відносним до `$ORIGIN` шляхом пошуку бібліотек, і завантажений голос у директорії `<prefix>/share/<project>`, тоді як пакет DEB залежить від системних пакетів onnxruntime і SDL2 через інструмент `dpkg-shlibdeps`. Flatpak і snap збирають `libpiper` так само з доступом до мережі, беруть SDL2 середовища виконання (snap - з архіву Ubuntu) і не завантажують голосу. Flatpak відтворює мовлення через сокет PulseAudio, читає голоси і записує файли параметра `--output` у домашній директорії, а snap відтворює його через інтерфейс `audio-playback`.
